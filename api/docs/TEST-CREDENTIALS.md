## Content visibility — most imported articles are still DRAFT

The 16 imported education articles and the 3 seeded quizzes land as `DRAFT`
by design (`scripts/import-content.ts` / `scripts/seed-quizzes.ts` — a human
reviews before anything goes live). A patient's `/api/education/bundle` and
`/api/quizzes/bundle` only return `PUBLISHED` content, so **right now the
mobile app will show the 6 pre-existing seed articles and 1 quiz**
(`smbg-quiz`, published during backend verification), not the 16 imported
topics, until an admin publishes them.

To publish everything for testing:

```bash
docker exec t1dpe-postgres-dev psql -U t1dpe -d t1dpe -c \
  "UPDATE \"EducationContent\" SET status='PUBLISHED', \"publishedAt\"=now() WHERE status='DRAFT';"
docker exec t1dpe-postgres-dev psql -U t1dpe -d t1dpe -c \
  "UPDATE \"Quiz\" SET status='PUBLISHED', \"publishedAt\"=now() WHERE status='DRAFT';"
```

Or, for the real workflow: sign in to `/admin/content/education`, open each
article, review the imported Markdown, and set status to Published from the
edit form.

## Regenerating this data

```bash
cd api
npm run db:seed              # fabricated participants + staff (skips if DB already has users)
npm run content:import       # the 16 drive documents -> EducationContent
npm run content:seed-quizzes # the 3 hand-transcribed quizzes
```

`db:seed` refuses to run against a non-empty database — reset the local
Postgres first if you want a clean slate:

```bash
docker exec t1dpe-postgres-dev psql -U t1dpe -d t1dpe -c \
  'TRUNCATE "User" CASCADE;'
```
